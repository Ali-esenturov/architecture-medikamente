# MVP: категории данных по доменам и доступ (RBAC/ABAC)

## Домен 1. Identity
- Данные: ФИО, дата рождения, `patient_id`
- Доступ:
1. `patient` (RBAC): только свои данные
2. `reception` (RBAC): чтение/обновление для записи
- ABAC правило: `subject.patient_id == resource.patient_id` для роли `patient`

## Домен 2. Contact
- Данные: телефон, email
- Доступ:
1. `patient`: только свои контакты
2. `reception`: чтение/обновление для напоминаний
- ABAC правило: доступ только при `purpose in {booking, reminder}`

## Домен 3. Appointment
- Данные: дата, время, специалист, статус записи
- Доступ:
1. `patient`: свои записи
2. `reception`: все записи филиала
3. `doctor`: только записи, где он назначен
- ABAC правило: `subject.doctor_id == resource.doctor_id` для роли `doctor`

## Домен 4. Notification
- Данные: канал уведомления, шаблон, статус отправки, время отправки
- Доступ:
1. `reception`: управление напоминаниями
2. `doctor`: просмотр статуса напоминаний по своим приемам
3. `patient`: просмотр своих уведомлений
- ABAC правило: уведомление связано с доступной записью (через `appointment_id`)

## Домен 5. Minimal Clinical (MVP)
- Данные: специализация врача, кабинет, минимум контекста для записи
- Доступ:
1. `reception`: чтение
2. `doctor`: чтение
3. `patient`: ограниченное чтение (без чувствительных медданных)
- Примечание: полные медкарты не входят в объем MVP.

## Базовые правила для MVP
1. Все доступы логируются.
2. По умолчанию deny, доступ только по роли/атрибуту.
3. Используется принцип минимально необходимого доступа.
