## 2) Механизм тегирования данных

## 2.1 Схема тегов

Предлагаемый формат:
`<class>.<criticality>.<domain>` + служебные атрибуты.

Примеры:
- `PID.HIGH.CORE`
- `MED.HIGH.CARD`
- `ANALYSIS.HIGH.LAB`
- `FIN.MEDIUM.BILLING`
- `OPS.MEDIUM.AUDIT`

Служебные атрибуты (metadata):
- `owner` - владелец данных (роль/подразделение)
- `retention` - срок хранения
- `lawful_basis` - основание обработки
- `consent_required` - требуется ли явное согласие
- `export_policy` - правила экспорта/выгрузки

## 2.2 Правила применения тегов

1. Тег присваивается в момент создания записи (форма записи, медкарта, оплата, анализ)
2. Теги наследуются при копировании/экспорте данных
3. Любая выгрузка без тега блокируется политикой DLP
4. Права доступа определяются комбинацией `role + tag` (RBAC/ABAC)
5. Для тегов `HIGH` обязательны: MFA, расширенный аудит, запрет открытых каналов передачи

## 2.3 Инструменты тегирования

- Каталог метаданных/классификатор данных (data catalog)
- Политики DLP/CASB, читающие теги и применяющие правила
- Labeling/Classification на уровне документов и БД
- SIEM для корреляции событий по тегам
- IAM/ABAC engine для авторизации по атрибутам

## 3) Инструменты, способы и меры для конфиденциальности по потокам

## 3.1 Запись пациента
- Единая цифровая форма с обязательной валидацией и минимизацией полей
- TLS 1.3 для всех каналов, шаблоны уведомлений без медданных
- Шифрование хранилища записей (AES-256), RBAC для ресепшен/медиков
- Логирование создания/изменения/просмотра записей

## 3.2 Прием и медкарта
- Переход с Excel/PDF/JPG на централизованный EMR
- Field-level security для диагнозов и чувствительных полей
- Псевдонимизация patient_id в аналитических витринах
- DLP-контроль экспорта, immutable audit log

## 3.3 Оплата и бухучет
- Исключить двойной мастер-учет в Excel; единый мастер-источник в 1С/центральной системе
- mTLS и подпись событий ККМ при интеграции
- Токенизация платежных идентификаторов в отчетах

## 3.4 Анализы
- Хранение результатов только в защищенном модуле/хранилище
- Подпись лабораторного результата для контроля целостности
- Доступ пациента через личный кабинет (без email-вложений)
- Обезличенные выгрузки для исследований/статистики

## 4) Базовые организационные меры

- Политика классификации данных и матрица доступа по ролям
- Регламент жизненного цикла данных: сбор -> хранение -> использование -> архив -> удаление
- Регулярный аудит прав, quarterly recertification доступов
- План реагирования на инциденты и тренировки
- Обучение сотрудников по работе с ПДн и медтайной
